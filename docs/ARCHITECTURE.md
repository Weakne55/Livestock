# Архитектура пайплайна Livestock

## Основная идея

Snakemake читает YAML и TSV, строит DAG зависимостей и запускает задачи без ручной передачи результатов между стадиями. Все вычислительные правила определены в `workflow/Snakefile` и девяти `workflow/rules/*.smk`; тяжёлые задачи исполняются внутри единого SIF. Для каждого вида используются собственные FASTA и индексы.

## Этапы и единицы параллелизма

| Этап | На какой единице выполняется | Результат |
|---|---|---|
| `prepare_reference`, `index_reference` | Вид + сборка | FASTA/FAI и индекс BWA/BWA-MEM2 в кеше |
| `trim_fastq` | Sequencing unit `(sample, library, lane)` | Очищенные paired FASTQ и JSON/HTML fastp |
| `align_lane` | Sequencing unit | BAM одной lane с read groups |
| `canonical_bam` | Образец | Итоговый BAM и BAI |
| `bam_qc` | Образец | flagstat, stats, mosdepth |
| `call_highcov_contig` | Образец × хромосома | BCF **одного highcov-образца** |
| `call_lowpass_contig` | Образец × хромосома | BCF отдельного lowpass-образца |
| `highcov_vcf`, `lowpass_vcf` | Образец | Индивидуальный VCF.gz + TBI |
| `highcov_stats`, `lowpass_stats`, `multiqc` | Соответствующий VCF / набор отчётов | Статистика и HTML MultiQC |

**FASTQ не разбиваются на искусственные чанки**: одно выравнивание на sequencing unit. Несколько lanes *одной* библиотеки объединяются перед postprocessing. Разные библиотеки одного животного в этой реализации не поддерживаются валидатором.

### Ветвь FASTQ

1. `fastp` обрабатывает R1/R2 и сохраняет JSON/HTML.
2. `bwa` или `bwa-mem2` выравнивает чтения; `samtools view` записывает lane BAM с `@RG`.
3. `samtools merge` (если lanes несколько), `collate`, `fixmate -m`, `sort`, `markdup`, индексирование.
4. Созданный `workdir/bam/<sample>.bam` **не** является `temp()`.

### Ветвь BAM/CRAM

Заголовок проверяется на `SO:coordinate`, соответствие `@RG SM` идентификатору образца и согласованность contigs/длин с FASTA. Входные BAM/CRAM переводятся в итоговый BAM, **без скрытого повторного markdup**. Пользователь отвечает за качество и предварительную политику дубликатов готового выравнивания.

### Variant calling

В обоих режимах `bcftools mpileup -Ou | bcftools call -m -v` обрабатывает **один BAM на образец** по конфигурируемым хромосомам. Для highcov применяется нормализация и пометка `FILTER=LowQual` ниже порога; lowpass получает индивидуальный variant-only VCF без импутации. Новые животные **не становятся входом** для повторного calling уже обработанных животных. Объединение генотипов в когорту пользователь выполняет отдельно после QC.

## Где хранятся файлы

`workdir`: BAM, BAI, chromosome BCF, временные trimmed FASTQ и lane BAM. `results_dir`: итоговые VCF/TBI, QC, benchmarks. `reference_cache_dir`: индексированный референс. При `keep_trimmed_fastq: false` и `keep_lane_bam: false` временные файлы удаляются Snakemake после успешного использования. Постоянные BAM нужно самостоятельно архивировать, если рабочую файловую систему очищает администратор.

## Методологические ограничения

1. Пример `contigs` содержит только аутосомы: варианты половых хромосом и митохондрии не вызываются. Ploidy не задаётся с учётом пола.
2. Исторические пилоты (октябрь 2026) проводились с одним WGS-образцом на вид; индивидуальная ветка highcov после изменения требует нового end-to-end теста. На больших выборках критичны число заданий Slurm, I/O и хранение BAM, но RAM одного highcov calling больше не зависит от размера когорты напрямую.
3. Lowpass VCF содержит обнаруженные варианты, но **не** является импутированной матрицей генотипов.
4. BQSR, SV/CNV, панели импутации и популяционно-генетический анализ в текущем workflow отсутствуют.
5. Техническое завершение workflow не доказывает биологическую корректность всех генотипов. Перед серьёзным исследованием потребуются QC и собственная схема фильтрации вариантов.
