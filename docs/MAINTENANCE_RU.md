# Обслуживание и диагностика Livestock

## Где смотреть состояние

На Vavilov запускайте контроллер из `~/livestock` на `vavilov0`:

```bash
squeue -u "$USER"
pgrep -af 'snakemake.*workflow/Snakefile' || true
ls -lt logs/controller-*.log | head
```

Статус целевого запуска определяется его конкретным `logs/controller-...log`, а не последним произвольным файлом. Для исторических Slurm-заданий:

```bash
sacct -S YYYY-MM-DD -u "$USER" -X \
  --format=JobID,State,ExitCode,Elapsed,AllocCPUS,ReqMem
```

Проверяйте журнал правила в `.snakemake/slurm_logs/`, если контроллер сообщает ошибку. `PENDING` само по себе не означает ошибку: задание может ждать ресурсов.

## Если анализ прервался

1. Убедитесь, что старый контроллер действительно остановился.
2. Изучите ошибку в controller log, log соответствующего Slurm job, затем устраните причину.
3. Перезапустите **тот же** workflow с **той же** конфигурацией и `workdir`; Snakemake переиспользует корректные результаты.
4. Не запускайте параллельный контроллер на те же файлы, не удаляйте незавершённые BAM/BCF вручную.

## Что можно очищать

- `__pycache__`, `*.pyc` — автоматически создаваемый кеш Python.
- `trimmed` и `lanes` — Snakemake удаляет самостоятельно, когда временные файлы больше не нужны и соответствующие флаги в YAML равны `false`.
- Исторические логи — переносите в архив запуска **после** завершения и проверки; не добавляйте в Git.

**Не удалять без копии и проверки:** `workdir/bam/*.bam` и `.bai`, конечные VCF, исходные FASTQ, референсы, конфигурацию фактического запуска, журналы и benchmarks. Промежуточные BCF не относятся к гарантированно удаляемым `temp()` и могут понадобиться для диагностики.

## Как сохранить итоговые BAM

```bash
WORK=/absolute/path/to/run/work
RESULTS=/absolute/path/to/run/results
mkdir -p "$RESULTS/bam"
rsync -avh --progress "$WORK/bam/" "$RESULTS/bam/"
```

Проверьте размеры и контрольные суммы копий до очистки scratch. Полная структура результатов — [OUTPUTS_RU.md](OUTPUTS_RU.md).

## Репозиторий Git

Код, шаблоны и документация хранятся в Git; большие SIF, FASTQ, BAM/VCF, реальные манифесты и логи — вне Git. Файлы `.gitignore` не очищают историю старых коммитов автоматически. Следите за `git status`, `git diff --cached --check` и `git ls-files` перед `git push`.
